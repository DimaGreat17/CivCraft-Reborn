# GDD-11 — Сквозные правила, технические ограничения и критерии качества

**PROPOSED / NOT FROZEN · 2026-11-18.** Это **игровые/системные инварианты**, а не код или окончательный выбор Fabric/версии Minecraft. Основано на [Engineering Standards](../04-architecture/ENGINEERING_STANDARDS.md), [GDD-02](./NPC_POPULATION_AND_BEHAVIOR_GDD_02.md), [G0 рисках](../01-legacy-audit/G0_SOURCE_RUNTIME_AND_RISKS_PASS_10.md).

## Инварианты проекта

- Всё богатство и ресурсы имеют источник, операцию и собственника; NPC не получают скрытых бесплатных запасов.
- Ни один гражданин/город/государство не исчезает из истории из-за выгрузки чанка, смены политического владельца или обычного рестарта.
- Все системные изменения происходят на сервере, с проверкой полномочий.
- Один `OperationId` исполняется максимум единожды; повтор события после сбоя безопасен.
- Два хранилища/перевозчика не могут одновременно владеть одним грузом.
- Границы мира, технологические AND-входы, условия победы проверяются для player и NPC.
- Слой Minecraft Entity — временная визуальная/физическая проекция долгосрочного `CitizenId`; нет раздвоения при materialization.
- Песочница не завершается достижением победы; конечный режим завершает партию только законной финальной процедурой.
- Устаревшая/неподтверждённая историческая механика никогда не маркируется как подтверждённый источник.

## Время

Три категории часов: **игровое время мира** для потребностей и труда, **время активного сервера** для согласованных долгих расчётов и **реальное время** только для явно выбранных правил. Не приравнивать 21 реальный день старого публичного сервера к 21 дню Minecraft без решения. Остановленный singleplayer/сервер не начисляет неограниченную экономику в фоне.

## Simulation LOD

`Loaded` — физические NPC, блоки/сундуки/пути; `Virtual` — те же субъекты и товары в агрегированном расписании; `Transition` — единственный способ перенести состояние. Нет force-load миллионов чанков. Фоновый планировщик может читать immutable snapshot; Minecraft мир и блоки изменяются только в правильном серверном контексте.

**Proposed metrics:** MSPT/TPS, число entity, pathfinding time, размер очередей задач/транзакций, время сохранения, память, доля незавершённых резервов и время materialization. Конкретные бюджеты устанавливаются замерами на всех пресетах, не придумываются для красивой таблицы.

## Надёжность

Versioned saves, typed IDs, migrations, backup/recovery, детерминированные проверки, единый источник правды для NPC/ресурсов, bounded queues с retry/backoff, журнал смены собственности и строительных блоков. Старую SQL busy-spin очередь не копировать. Код/ассеты старого плагина не переносить до решения лицензий (GPL root vs file-level proprietary notices).

## Матрица отказов

| Событие | Обязательный результат |
|---|---|
| Crash после списания стройматериалов | Повтор безопасно завершает или явно компенсирует одну операцию, не дублирует |
| Выгрузка NPC в пути | Сохраняется один гражданин, job и груз |
| Изменение владельца города в середине выполнения работы | Полномочия переоцениваются; имущество не пропадает |
| Два игрока заканчивают уникальное чудо | Только одно подтверждённое завершение по правилам |
| Нападение на виртуальную поставку | Определяется единственный исход груза, никакой бесплатной второй поставки |
| Нет исходных данных/рецепта в wiki | Фича помечается UNKNOWN или исключается решением владельца; нет придуманного баланса |
| Изменение версии модпака | Миграция или контролируемое предупреждение, не тихое удаление цивилизаций |

## Требования к каждому будущему системному контракту G2

Каждая операция описывается: `Trigger → Actor/Authority → Input Preconditions → Resource/Permission Reservations → Time/Costs → Transition → Output/Event → Persistence → Failure/Compensation → Tests`. В GDD может оставаться список открытых опций, но до реализации контракт должен содержать принятое решение.

## Gate G4 — условия разрешения кодирования

1. G0 закрыт либо есть **явно утверждённое ограничение scope с известными неизвестными**, не затрагивающее выбранный релиз.
2. Все D-001–D-015 соблюдены; все владельческие решения со статусом `FROZEN` оформлены.
3. Граница первого патча определена без недоступных технологических/экономических prerequisite.
4. Готовы системные use-cases и архитектура: хранение, нити, сетевые полномочия, планировщик, события, LOD.
5. Согласованы измеримые тесты для размеров 10k/15k/25k.
6. Установлены условия правомерного использования исходников и ассетов.
7. Владелец явно принимает готовность к реализации, с перечнем всех исключённых возможностей.
