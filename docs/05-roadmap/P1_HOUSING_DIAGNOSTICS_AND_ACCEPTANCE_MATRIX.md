# P1 — Диагностика Housing, причины отказов и матрица проверки

**Статус: DESIGN_SELECTED_DELEGATED / DRAFT · 2026-11-18. Не реализовано.** UI — только представление server-authoritative данных [G2-10](../03-system-design/G2_P1_HOUSING_INTEGRATED_DOMAIN_CONTRACT.md).

## 1. Игрок должен видеть причинность

Для каждой обнаруженной комнаты выводить: **статус пригодности**, **кровати (доступные/занятые/в резерве)**, **собственные пригодные клетки пола**, **предварительная норма 4 клетки на NPC**, **вместимость**, **текущее заселение**, **комфорт** и **проверяемые причины ограничений**.

Варианты статуса в UI: `Пригодно / Недостаточно площади / Нет доступа / Нет укрытия / Опасно / Нет прав / Ожидается проверка / Требуется переселение`. Не скрывать `PENDING` за зелёным «готово».

## 2. Пользовательские поверхности

### Просмотр дома

- Ненавязчивая подсказка при наведении/взаимодействии с кроватью: пригодность, причина отказа, кнопка просмотра деталей (если есть права).
- Отдельный экран поселения показывает **суммарную вместимость, занятые места, потребность в жилье, число недоступных/повреждённых комнат**.
- В окне отдельной комнаты — число клеток именно этой жилой зоны, без общих лестниц/коридоров D-059; фактический список граждан доступен только уполномоченным.
- Для открытой общей спальни показывать **один** регион, не дублировать площадь для каждой кровати.
- Визуальная подсветка клеток — диагностическая проекция, не способ создать/«утвердить» жильё вручную.

### Админ и отладка

- Команда-кандидат `/civcraft housing inspect` — статус/ревизия/причины по target position, строго permission gated.
- Команда-кандидат `/civcraft housing metrics` — агрегаты: очередь dirty, p95 времени проверки, конфликтующие клетки, ожидающие зоны, mspt/tps. Не выгружать персональные координаты жителей всем игрокам.
- `/civcraft housing recheck` — только администратору и только **постановка в очередь**, не прямое создание жилья и не принудительная загрузка чанков.

**Команды — предлагаемые имена, не утверждённый CLI интерфейс.**

## 3. Формат диагностического snapshot (кандидат)

```text
HousingDiagnosticSnapshot {
  schemaVersion, regionId, settlementId, topologyRevision,
  checkedAtActiveGameTime, validationCompleteness,
  state, reasonCodes[],
  validBeds, assignedBeds, reservedBeds,
  exclusiveUsableFloorCells, provisionalAreaPerNpc=4,
  areaCapacity, housingCapacity, availableForNewAssignment,
  comfortBand, comfortEvidenceSummary,
  detailsPermission
}
```

Не отдавать клиенту `FloorCellId[]` или детали чужих домов без разрешений; запрос на подробную карту клеток можно ограничивать и обрезать. Клиент не вычисляет авторитетную вместимость.

## 4. Матрица UI причины → действие

| Серверная причина | Видимая строка | Возможное действие игрока |
|---|---|---|
| `NO_BED` | Нет доступных кроватей | Добавить реальную кровать |
| `INSUFFICIENT_PRIVATE_CELLS` | Недостаточно собственной жилой площади | Расширить безопасный доступный пол спальни |
| `TRANSIT_ONLY` | Общий коридор не считается жилым пространством | Изменить именно спальню, а не общий проход |
| `NO_SHELTER` | Помещение не защищено от внешней среды | Проверить крышу/проёмы |
| `NO_ACCESS` | NPC не может попасть к месту сна | Освободить проход, дверь, лестницу |
| `UNSAFE_SURFACE` | Часть пола опасна или непригодна | Устранить опасность/коллизию |
| `RIGHTS_DENIED` | Нет разрешения на заселение | Получить законное право |
| `UNLOADED_BOUNDARY` | Область пока не проверена | Дождаться естественной доступности области при игре; не force-load |
| `CELL_OWNER_CONFLICT` | Границы комнат требуют уточнения | Проверить перегородки, избегать двусмысленной планировки |
| `COMFORT_UNKNOWN` | Качество жилья ещё не оценено | Комфорт не даёт бонус до проверки |

Отображение пользовательского текста локализуется; точные сообщения/UX проверяются на читабельность.

## 5. Необманчивые метрики

- `assignedCount` не равен общему числу жителей поселения; бездомные/переселяемые граждане учитываются отдельно.
- Комфорт не увеличивает `housingCapacity` и не начисляет city happiness без утверждённой отдельной модели.
- При сжатии вместимости до значения ниже текущей занятости показывать и **реальную вместимость**, и **нуждающихся в переселении**, а не скрывать людей.
- Обозначать неподтверждённую квартиру `PENDING` без агрессивного самопроизвольного выселения.

## 6. Тесты диагностики DIAG-01…12

| ID | Что проверяем |
|---|---|
| DIAG-01 | При 8 приватных клетках и 2 кроватях отображаются 2 места по provisional D-056 |
| DIAG-02 | Общий коридор не входит в `exclusiveUsableFloorCells` |
| DIAG-03 | Барак — один жилой регион без удвоения кроватей/площади |
| DIAG-04 | Нет проходимой лестницы — `NO_ACCESS`, а не «успешно» |
| DIAG-05 | Комфорт GOOD не повышает вместимость |
| DIAG-06 | Перестройка вызвала `PENDING`, UI не обещает новых мест |
| DIAG-07 | Обычный игрок не видит приватные координаты чужих жилых зон |
| DIAG-08 | Подделка сетевого клиентского пакета не делает комнату валидной |
| DIAG-09 | После restart status/revision не дают несогласованных новых заселений |
| DIAG-10 | Неполная загрузка чанков показывает ожидание без force-load |
| DIAG-11 | Повреждённый дом показывает число жильцов под переселение без удаления NPC |
| DIAG-12 | Показатели p95/queue не требуют сканировать всё поселение при открытии меню |

## 7. Приёмка в P1

Сначала модульные симуляционные тесты, затем Minecraft dedicated + singleplayer. UI тестируется только по server snapshots. Обязательны локализация, отказ доступа, отмена просмотров, долговременный тест массовых изменений и отсутствие падений TPS. Значения budget/performance пока OPEN и не выдаются за пройденные измерения.
