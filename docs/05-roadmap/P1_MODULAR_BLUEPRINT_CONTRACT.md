# P1 — MODULES: контракт модульных функциональных построек

**Статус:** D-051 APPROVED_CONCEPT (2026-11-18); подробные правила PROPOSED / NOT FROZEN.  
**Связанные решения:** D-019, D-023–D-025, D-049, D-050, D-051.  
**Граница:** документы проектирования P1/0.2; НЕ игровой код P0. P1 нельзя запускать без приёмки P0 и отдельного утверждения состава P1.

## 1. Зафиксированное решение

Функциональная постройка создаётся **по модульному чертежу**. У неё есть **обязательные функциональные части**, но допустимы изменения формы, размеров и оформления **в пределах проверяемых правил**. Успех определяется сервером по реально существующим блокам, доступности, правам и учёту затрат, а не только по проекции чертежа или кнопке.

Это **не** фиксированная копия блок-в-блок и **не** произвольная группа рабочих блоков без пространственных требований. Обычные дома и декор по D-050 по-прежнему строятся свободно, без чертежа.

## 2. Предлагаемая структура BlueprintDefinition

| Поле | Назначение | Статус |
|---|---|---|
| `BlueprintId`, `BlueprintVersion` | Стабильная схема и её версия; старые сохранения не переопределяются молча | PROPOSED |
| `BuildingClass` | Категория функции (склад, мастерская и т.п.), не политический статус | PROPOSED |
| `Anchor`, `Orientation` | Опорная точка относительно ядра лагеря; ориентация и преобразование координат | PROPOSED |
| `RequiredModules[]` | Обязательные физические модули с количеством, ролями и условиями | PROPOSED |
| `OptionalModules[]` | Дополнительные части, не обязательные для базовой активации | PROPOSED |
| `AllowedGeometry` | Проверяемые ограничения размеров, расстояний, связности и пересечения | PROPOSED |
| `AllowedBlockTags` | Группы взаимозаменяемых материалов, если это утверждено для конкретного модуля | PROPOSED |
| `AccessRules` | Вход, доступ работников и физические пути к рабочим блокам | PROPOSED |
| `ResourceLedgerRef`, `WorkTickets` | Единственный источник списания/поставок и реально выполненных работ | PROPOSED |
| `ValidationRevision` | Результат серверной проверки по конкретной версии чертежа и мира | PROPOSED |

Система чертежей не должна импортировать старые схематики CivCraft без проверки прав по D-048.

## 3. Группы модулей (предлагаемая классификация)

- **Ядро функции:** рабочий блок, контейнер, производственный узел либо другой объект, без которого здание не выполняет роль.
- **Инфраструктура:** физическая опора, допустимая площадка, ограждение или зона размещения, если конкретный тип здания этого требует.
- **Доступ:** достижимые точки использования для игроков и NPC, без нарушения чужой собственности и защищённых территорий.
- **Вспомогательные модули:** дополнительные ёмкости, рабочие места, украшения; эффекты и лимиты будут утверждаться отдельно.

Пример **не утверждённой схемы**: склад = опорная зона + один обязательный контейнер + доступ к нему; дополнительные контейнеры дают расширение после проверки. Это только иллюстрация контракта, не финальный рецепт/размер и не историческая механика.

## 4. Как игрок строит модульное здание (предложение)

1. Выбирает доступный чертёж и место в действующем лагере.
2. В режиме предварительного просмотра вращает и адаптирует разрешённые модули; UI отдельно показывает обязательные и необязательные части, ограничения, фактические затраты и конфликты.
3. Сервер валидирует участок, права, запрошенную конфигурацию, границу мира, доступность материалов и отсутствие конкурирующей стройки. Клиентская проекция не подтверждает готовность.
4. Создаётся `ConstructionId`, резервируется согласованный план. **Пустые блоки из воздуха не возникают**.
5. Игрок и/или NPC доставляют реальные материалы и размещают физические блоки в разрешённых позициях; работа записывается в единый журнал.
6. Сервер проверяет каждый обязательный модуль, связность, доступ и действительное состояние блоков. При выполнении требований переводит здание в `ACTIVE`; иначе объясняет конкретные недостающие элементы.
7. Позже игрок изменяет декоративные части свободно; если изменены обязательные элементы, идёт повторная проверка и возможный статус `DAMAGED/INCOMPLETE`.
8. Версии схем, блоки, материалы и состояние работ сохраняются; после crash/reload требуется сверка, а не повторное создание ресурсов.

## 5. Формальная проверка (проект)

`CanActivate = Authorized && ValidSite && EveryRequiredModuleValid && GeometryValid && AccessValid && MaterialAndWorkLedgerConsistent && NoClaimConflict`.

Проверка геометрии выполняется по снимку/ревизии действительных блоков; при конкурирующем изменении повторяется на сервере. Проверка не должна force-load миллионы чанков. При отсутствии необходимых загруженных данных результат `PENDING_VERIFICATION`, не ложное `ACTIVE`.

Ограничения **открыты**: насколько допускается произвольная ориентация, какой модуль может быть заменён ванильным блоком, когда модуль считается разрушенным, что делать с многоэтажными и перекрывающимися помещениями.

## 6. NPC и расширение постройки

NPC видят тот же `ConstructionId` и список незавершённых `WorkTickets`. Работник может получить задание на транспортировку, установку разрешённого блока либо ремонт. Задача не начинается без физического инвентаря и разрешённого пути. В unloaded/virtual режиме результаты должны быть эквивалентны физической работе по времени, затратам, ограничениям и рискам; мир после загрузки синхронизируется без дублирования. Нельзя одновременно начислять таймерную продукцию и предметы за действия NPC.

Добавление вспомогательного модуля потенциально изменяет вместимость или возможности **только по отдельно утверждённому эффекту**. Здание не начинает производить ресурсы автоматически из-за лишнего контейнера.

## 7. Защита и жизненный цикл

- Доступны статусы `DRAFT, RESERVED, UNDER_CONSTRUCTION, VERIFYING, ACTIVE, PAUSED, INCOMPLETE, DAMAGED, UNDER_REPAIR, CANCELLED` — **кандидат**, не согласованный enum.
- Уничтожение обязательного модуля прекращает или ограничивает его функцию после проверки, не удаляя собственность и историю.
- Свободное строительство вокруг проекта разрешено, пока не нарушены строительные и правовые ограничения.
- Конфликтующие чертежи блокируются; нельзя присвоить чужую постройку или автоматически стереть чужие блоки.
- Отмена проекта освобождает **неиспользованные** резервы, уже размещённые блоки остаются регулируемыми обычными правами на Minecraft-мир.
- Замена версии чертежа на существующем здании требует явной миграции, не автоматического сноса/переделки.

## 8. Приёмочные проверки (предложения)

| ID | Сценарий | Результат |
|---|---|---|
| PMOD-01 | Два отличающихся внешне склада соответствуют одному модульному чертежу | Оба активируются с одинаковой базовой функцией |
| PMOD-02 | Удалён обязательный рабочий модуль | Функция недоступна или деградирует по контракту |
| PMOD-03 | Переставлена свободная декоративная часть | Функция сохраняется, если правила геометрии не нарушены |
| PMOD-04 | Отсутствует вход или физический доступ NPC | Указана причина отказа, нет фиктивной работы |
| PMOD-05 | Конструкция пересекает чужую территорию или worldborder | Сервер отклоняет даже при разрешающем UI |
| PMOD-06 | Два клиента завершают один модуль одновременно | Один учёт расхода/строительства |
| PMOD-07 | Отмена или разрушение после резервирования | Неиспользованные резервы освобождаются, предметы не клонируются |
| PMOD-08 | Сервер выключен после размещения блоков, до записи результата | Recovery сверяет физические блоки и журнал, не создаёт второго здания |
| PMOD-09 | NPC использует только действующий доступный модуль | При повреждении прекращает связанную работу |
| PMOD-10 | Дальний виртуальный работник и локальный работник с одинаковыми входами | Нет бесплатных блоков, материала, времени или двойных задач |
| PMOD-11 | Изменена версия чертежа | Старое здание остаётся валидным по своей версии до явной миграции |
| PMOD-12 | Обычный дом построен свободно без чертежа | Нет обязательного чертежа; жильё/NPC-слоты определяются отдельно |

## 9. Ближайшие открытые решения

1. **Материалы модулей — HYBRID утверждён (D-052):** стандартные блоки Minecraft для конструкции, специальные блоки мода для уникальных функций только при необходимости. Конкретные блоки/теги и рецепты остаются открыты.
2. **Свобода геометрии:** интервалы размера и дистанций, перенос модулей, допуск многоэтажных планировок.
3. **Жильё NPC:** отдельный распознаватель свободного дома, кровати, безопасного входа и пригодности.
4. **Каталог P1:** первые полноценные типы модульных зданий, без смешения с неподтверждёнными эффектами legacy.
5. **Баланс:** стоимость материалов, время работ, ограничения количества модулей, сроки ремонта.
6. **UI:** управление модульным чертежом, объяснение отказов и права совместного строительства.
