# P1 — FLOOR: пригодная площадь пола для жилья NPC

**APPROVED_CONCEPT:** D-055 (2026-11-18). Метрика вместимости — **пригодная площадь пола** в проверенных комнатах, а не трёхмерный объём воздуха. Всё далее о методе обхода, размерах, высоте, порогах и алгоритмах — **PROPOSED / NOT FROZEN**.

## 1. Совместимость с принятыми решениями

- D-053 ROOM: кровать, укрытие, реальный доступ и безопасность обязательны.
- D-054 COMBINED: число жильцов ограничено **и кроватями, и пригодным пространством**; комфорт отдельно влияет на удовлетворённость, не увеличивая число мест.
- D-055 FLOOR: в качестве измерения пригодного пространства используем **площадь пола**, не кубический объём.
- D-050: свободные дома не требуют чертежа. D-049: жилые места связаны с существующей территорией/правами лагеря.
- **FLOOR не означает**, что NPC могут проходить через потолок в один блок: доступность и реальные коллизии сохраняются из ROOM. Однако численная норма высоты пока НЕ утверждена и не должна скрыто подменять FLOOR решением HYBRID.

## 2. Проектный подсчёт пригодной площади

Единица-кандидат — `FloorCell` (горизонтальная позиция X/Z **и уровень Y**), содержащая опорную поверхность, на которой NPC действительно способен стоять, и достаточную фактическую проходимость по правилам передвижения. Каждый валидный элемент в пределах комнаты даёт определяемую площадь; сколько именно площади даёт неполный блок/ступень — открытый вопрос.

`UsableFloorArea = countDistinct(ValidatedWalkableFloorCellsOwnedByHousingRegion) × AreaPerCell`

Внешний контур дома не равен пригодному полу. Не учитываются непроходимые элементы, опасные поверхности, блоки за запретными дверями и участки без связи с кроватью по допустимому пути. Коллизии и доступ определяются физическими Minecraft-состояниями, а не только типом блока. Конкретные правила для плит, ступеней, ковров, воды, люков и модовых блоков требуют подтверждения.

**Многоквартирный дом / этажи:** этажи допускают самостоятельные горизонтальные ячейки с разным `Y`; площадь каждого этажа может учитываться, если она пригодна, достижима и отнесена к соответствующему жилищу. Одна ячейка не может одновременно увеличивать вместимость двух независимых помещений. Правила общих коридоров и комнат ещё не утверждены.

## 3. Вместимость (предлагаемый контракт, не баланс)

Если все требования ROOM выполнены:

`HousingCapacity = min(UsableBeds, floor(UsableFloorArea / RequiredAreaPerCitizen))`

Иначе `HousingCapacity = 0` для новых назначений. Это **иллюстрация математического ограничения**, не готовая утверждённая формула; минимум площади на одного жителя и способы округления не утверждены. Комфорт остаётся отдельным `ComfortScore` и не добавляет места.

Нельзя выдавать дополнительные места за свободный вертикальный объём, высокий потолок или комнату с одним матрасом и десятью этажами без корректного маршрута.

## 4. Ограниченный обход геометрии (предложение G3)

1. Событие кровати или значимых блоков ставит локальную комнату на перепроверку.
2. Сервер нормализует двухблочную кровать в одну опорную запись и выбирает входные точки.
3. Выполняет ограниченный обход достижимых **поверхностей пола** в загруженной области, связывая допустимые этажи путями (лестницы и т.п.); проверяет границу, убежище и безопасность.
4. Каждая ячейка получает canonical owner `HousingRegionId`, чтобы избежать двойного подсчёта между комнатами/перекрытиями.
5. Если достигнут лимит обхода или отсутствуют данные чанка — `PENDING_VERIFICATION`, не автоматическое признание полной площади.
6. Кешировать результат по версии проверенной геометрии; изменения релевантных блоков инвалидируют конкретную область, а не весь мир.
7. Сохранять подтверждённые площади, привязанные кровати, `RoomId`, назначения и версию правил; при восстановлении не выдавать новых слотов, пока неизвестные участки не сверены.

**OPEN:** точный предел поиска, связи между этажами, высота прохождения, жидкие и частичные блоки, соседство чужих участков, общие зоны и алгоритм определения помещений без многократного force-load.

## 5. Игровая диагностика (предложение)

В панели жилья показывать: пригодные кровати, подтверждённая площадь пола, пространственный лимит жильцов, текущее заселение, комфорт и причины исключения отдельных участков («нет доступа», «опасный пол», «закрытая зона»). Декор не влияет на вместимость, если не изменяет физическую доступность пола.

## 6. Тестовый набор FLOOR-01…12

| ID | Проверка |
|---|---|
| FLOOR-01 | Дом с большой высотой, но малым пригодным полом не увеличивает вместимость из-за объёма воздуха |
| FLOOR-02 | Расширение достижимого безопасного пола увеличивает площадь, но не превышает число кроватей |
| FLOOR-03 | Изменение оформления потолка без изменений пола/доступа не добавляет жилых мест |
| FLOOR-04 | Второй этаж с безопасным достижимым проходом может учитывать отдельные ячейки пола |
| FLOOR-05 | Недостижимая антресоль или перекрытая лестница не даёт дополнительных пригодных ячеек |
| FLOOR-06 | Ступени/плиты/модовые коллизии проверяются по явным правилам, не по одному названию блока |
| FLOOR-07 | Одна ячейка пола не считается дважды между комнатами или соседними жилищами |
| FLOOR-08 | Кровать, находящаяся снаружи пригодного ROOM, не становится жилым слотом за счёт площади соседнего дома |
| FLOOR-09 | Изменение пола инвалидирует локальный кеш проверки, не пересчитывает весь мир |
| FLOOR-10 | Недоступный чанк или превышенный бюджет обхода не создаёт ложной площади |
| FLOOR-11 | После перезапуска сервера площадь/назначения не удваиваются |
| FLOOR-12 | Замена дорогого декора, без изменения пригодных ячеек, не увеличивает вместимость, хотя отдельно может изменить комфорт |

## 7. Следующие вопросы перед P1 freeze

1. **Предварительный норматив D-056:** 4 пригодных блока² на одного NPC для тестирования. Число не FROZEN: требуется проверка на реальных постройках и баланс раннего лагеря.
2. **PHYSICAL D-057 утверждён:** пригодность плит, ступеней и иных блоков определяется реальной коллизией, проходимостью и безопасностью для NPC, а не типом. Дробный/целый вклад клеток, конкретные коллизии и размеры проходов остаются открыты.
3. Многоэтажность, лестницы, отдельные комнаты и учет общего коридора.
4. Правила разграничения жилья в одном большом сооружении.
5. Точные таймеры перепроверки и безопасного переселения при потере площади.
6. Визуальное выделение засчитанных/непригодных ячеек и контроль нагрузки.
