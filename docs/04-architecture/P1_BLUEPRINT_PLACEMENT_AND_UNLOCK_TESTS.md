# P1 / 0.2 — Тестирование размещения чертежей и разблокировки построек

**Дата:** 2026-11-18. Статус: DEVELOPMENT, не релиз 0.2. Проверки GUI/FPS должны пройти в клиенте Minecraft 26.3; CI сборки сам по себе не подтверждает визуализацию.

## Путь игрока

1. Создать мир с включённым «Мир CivCraft». Установить реальный `camp_core`; после каждого размещения получить 4 обсидиана. ПКМ по центру → интерфейс управления лагерем → «Схема строительства».
2. Пока не основан лагерь, серверное разрешение даёт **только HEART**. Требуется положить четыре настоящих блока обсидиана N/S/E/W вокруг центра.
3. Выполнить ресурсное основание `/civcraft camp found`. Ещё раз ПКМ по центру → теперь каталог показывает **только 6 базовых**: HEART, STORAGE, WORKSHOP, FARM, BEDROOM, SMALL_HOUSE.
4. Выбрать, например, SMALL_HOUSE → экран «Размещение». Нажимать Север/Юг/Запад/Восток по одному блоку, поворачивать влево/вправо на 90°. Схема ограничена радиусом 24 блока от зарегистрированного центра; сердце неподвижно.
5. Нажать «Материалы»: для каждого типа увидеть `всего требуется / уже стоит / в инвентаре / нужно добыть`. Для грядки показана земля и указана необходимость мотыги; для кровати подойдёт любой цвет.
6. Нажать «Показать проекцию в мире», установить недостающие блоки и проверить, как соответствующие объёмы исчезают. Разрушить блок, затем убедиться, что призрачный объём появляется снова.
7. Подтвердить реальные требования сервера отдельно через `/civcraft camp plan`, `/civcraft camp inspect`. Визуальная схематическая идентичность не равна действительности ROOM/PHYSICAL/rights.
8. Получить 3 проверенных жилых региона, 3 зарегистрированных жителей, 16 реальных еды в контейнерах, мастерскую и ферму, выполнить `/civcraft camp promote`.
9. ПКМ по центру заново → сервер разрешает дополнительно BARRACKS, GRANARY, SMITHY, WATCHTOWER, WELL.

| PLACE-15 | Клиент подделал stage / blueprint selection | Серверная регистрация лагеря/функциональность не меняется |

| PLACE-20 | FPS и рендер | Несколько крупных шаблонов не вызывают непрерывного роста памяти или ошибок GPU |

## Известные ограничения

- Полнообъёмная проекция пока рисует однотонные полупрозрачные кубы, не настоящие текстуры или формы отдельных BlockState.
- Ведомость считает блоки для прямой установки, не полные рецепты крафта и не запасы общих сундуков.
- Если игрок самостоятельно построил развитую постройку из ванильных блоков, это не означает разблокировки её игровой функции: вводимое ограничение относится к **каталогу схем**, а бонусы поздних уровней потребуют отдельной серверной механики.
- Перемещение проекции хранится только на клиенте на время выбранного чертежа; не создаётся отдельного постоянного строительного заказа.
- Эти 20 проверок — **план приёмки**, а не список пройденных игровых тестов.

## Основные файлы

- `settlement/BlueprintAccess.java` и `BlueprintNetworking.java` — серверные разрешения.
- `settlement/BlueprintTransform.java` — чистый контракт геометрии, есть unit-тесты.
- `client/CampBlueprintProjection.java` — состояния и материальная ведомость.
- `client/CivCraftBlueprintScreen.java` — каталог по стадии.
- `client/CivCraftPlacementScreen.java` — сдвиг/вращение.
- `client/CivCraftMaterialsScreen.java` — материалы и недостаток.
- `client/CivCraftGhostBlockRenderer.java` — проекция в мире.
