# P1 — Интернет-референсы и игровые заготовки построек

**2026-11-18 · Implemented as ORIGINAL CivCraft blueprint templates, no third-party .schem/.litematic files repackaged.**

## Задача

Игрок строит реальные блоки Minecraft; меню лагеря открывает каталог 3D-проекций. По выбранной схеме клиент рисует отсутствующие блоки, прогресс считается по реально установленным блокам, но никакие постройки/предметы не появляются бесплатно. Подсчёт функциональных зданий, жилья и прав должен выполняться на сервере; **совпадение декоративной проекции не равно автоматической регистрации здания**.

## Ограничения и технический долг

- **UI / рендер:** пока показываем полупрозрачные объёмы полных кубов, а не текстуры/точный BlockState Mesh. Не все ступени, кровати и заборы будут совпадать с точной формой в проекции.
- **Дверные проёмы:** шаблон оставляет проход пустым, пользователь вправе поставить дверь сам; для HOUSE/ROOM сервер должен проверять физический доступ.
- **Блоки с направлением/мультиблочностью:** кровать отмечается одной точкой-«якорем» с `anyBed`, дверь/лестница/полосы кровати пока не требуют заданного facing. Это нужно реализовать перед релизом.
- **Участок:** шаблоны привязаны к Camp Core, но нет пользовательского переноса/вращения схем и проверки пересечения существующих построек. Особенно важно при неровной поверхности и большой деревне.
- **Прогресс:** визуальный клиентский результат не является серверным доказательством пригодности ROOM/PHYSICAL/CELL, прав или склада. Нельзя начислять рабочие места или вместимость лишь по совпадению с призрачными блоками.
- **Проверка:** необходимо пройти Minecraft client smoke на 26.3 с 11 шаблонами, проверить видимость/кадровую скорость/повороты/правильные блоки и отдельный dedicated smoke. Пока не утверждать как завершённую 0.2.

## Следующее расширение

1. Разрешить игроку выбирать точку начала строительства отдельно от сердца, двигать и вращать чертёж.
2. Сделать категоризацию по размеру лагеря и уровням технологий, без обязательного строительства всех декоративных схем.
3. Подключить server-authoritative blueprint module matching только для функциональных строений.
4. Добавить фактическую полупрозрачную текстурированную форму Minecraft BlockState, а также material bill + недостающие ресурсы.
5. Для чужих лицензированных schematic-файлов предусмотреть отдельный импортёр с указанием авторства/условий, без автоматического включения сторонних файлов.
