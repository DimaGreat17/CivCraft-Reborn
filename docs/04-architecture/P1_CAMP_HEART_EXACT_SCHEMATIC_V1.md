# Camp Heart — точная поблочная схематика v1

**Дата:** 2026-11-19 · **Статус:** авторский технический прототип, требуется визуальная и клиентская приёмка.  
**Размер:** 7×7×6; координаты X,Z = −3…3, Y = 0…5. **Вход:** на юг (+Z). **Якорь:** `camp_core` в (0,0,0).  
**Источник:** оригинальная схематика CivCraft, вдохновлённая общим стилем ранних деревянно-каменных домов. Чужие схематики не копируются.

## Обозначения

| Символ | Блок |
|---|---|
| `C` | `civcraft_reborn:camp_core` |
| `S` | `minecraft:cobblestone` |
| `P` | `minecraft:oak_planks` |
| `L` | `minecraft:oak_log` |
| `W` | `minecraft:glass_pane` |
| `D` | `minecraft:oak_door lower/upper` |
| `<` | `minecraft:spruce_stairs west` |
| `>` | `minecraft:spruce_stairs east` |
| `=` | `minecraft:spruce_slab` |
| `·` | `air / no required block` |

На каждой карте: **верхняя строка = север (Z=−3)**, слева запад (X=−3), справа восток (X=+3). Дверь на координатах (0,1,3) и (0,2,3), две половины одного предмета.

Итого **161 предметов** при отсутствии готовых блоков на площадке, из них **1 специальное основание**, и **162 заданных ячеек**. Материалы показывать по реальным целевым позициям, дверь — единый предмет на две половины. `camp_core` устанавливается до начала строительного этапа; не списывать его вторично. Стеклянные панели должны автоматически соединяться с соседними блоками; при валидации сравнивать основные свойства, но не производные от соседей состояния соединений.

## Детали реализации

- Начальная ориентация фиксируется схемой; при повороте на 90° преобразовывать и координаты, и ориентированные `BlockState` (направление лестниц/двери). Половины двери сверять атомарно.
- `camp_core` в центре пола остаётся реальным якорем; интерфейс можно открыть ПКМ по нему. Прямой доступ сверху может требовать визуальной маркировки; голограмму переключать через меню.
- Полный первый лагерь игрок строит **только вручную**. У первого лагеря нет необходимости в молоточках. Автоматизация в других зданиях — отдельный следующий этап.
- Схема должна оставаться в мире независимо от UI, позиции и ориентация должны пережить перезапуск.
- Размещение до подтверждения: не сдвигать физический `camp_core`, а передвигать положение схемы только при условии, что её обязательная ячейка якоря по-прежнему совпадает с реальным блоком. Это ограничивает перенос; для действительно свободного перемещения нужен отдельный режим предварительной виртуальной привязки или перенос основания до подтверждения.
- Игрок может заранее ставить верные блоки; сервер считает совпадения по факту. Строгие проверки прав, границы мира, загруженности чанков, перекрытия чужих зданий.
- Проверка 완료: `PHYSICALLY_COMPLETE` только после проверки всех обязательных физических позиций. Отдельное `Основать лагерь` создаёт CampId и открывает функции.
- Владелец может позже повредить постройку; статус должен измениться на `DAMAGED`, без потери идентичности лагеря.

## Неопределённости

- Окончательный художественный вид: крыша имеет широкую верхушку из центральной плиты и верхнего ряда ступеней, в игровом клиенте требуется визуально проверить стыки.
- Рецепт основания и старая награда 4 обсидиана остаются отдельно на согласовании.
- Варианты блоков других пород дерева/повороты/замены при строительстве пока не предусмотрены в строгой v1-схеме.
